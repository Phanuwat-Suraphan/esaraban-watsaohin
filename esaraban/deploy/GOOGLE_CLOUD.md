# ติดตั้งบน Google Cloud "Always Free" (e2-micro)

Google Cloud ให้เครื่อง e2-micro ฟรีถาวร (ไม่ใช่ทดลองใช้ 12 เดือน) พร้อมดิสก์ 30 GB
เหมาะกับโรงเรียนที่ Oracle Cloud ไม่รับบัตร เพราะเป็นระบบตัดบัตรคนละเจ้ากัน

ขั้นตอนหลังสร้างเครื่องเสร็จเหมือน [`DEPLOY.md`](../DEPLOY.md) ทั้งหมด หน้านี้เขียนเฉพาะ
**เรื่องที่ต่างจากที่อื่นและพลาดกันบ่อย** โดยเฉพาะข้อ 3 ซึ่งเป็นข้อที่ทำให้ระบบล่มได้จริง

## สิ่งที่ต้องรู้ก่อนตัดสินใจ

| เรื่อง | ค่า | ผลต่อโรงเรียน |
|---|---|---|
| RAM | **1 GB** | น้อย — ต้องเพิ่ม swap ดูข้อ 3 |
| ดิสก์ | 30 GB (ต้องเป็นชนิด Standard) | เหลือเฟือ ดูหมายเหตุท้ายหน้า |
| ข้อมูลขาออกฟรี | **1 GB/เดือน** | ครูเปิดไฟล์ PDF ได้ราวเดือนละ 1,000 ครั้ง |
| ภูมิภาคที่ฟรี | เฉพาะ `us-west1` `us-central1` `us-east1` | จากไทยหน่วงราว 200 ms หน้าเว็บจะหนืดกว่าอยู่สิงคโปร์ |
| เกินโควตา | **คิดเงินส่วนเกิน ไม่ตัดบริการ** | ระบบไม่ล่มกลางเทอมเหมือน Render แต่ต้องมีบัตรใช้ได้ค้างไว้ |
| สถาปัตยกรรม | x86_64 | `DEPLOY.md` ใช้ได้ทั้งหมดไม่ต้องแก้ |

## 1. สร้างโครงการและเปิดการเรียกเก็บเงิน

สมัครที่ <https://console.cloud.google.com/> ต้องผูกบัตรเพื่อยืนยันตัวตนและเพื่อรับส่วนที่เกินโควตา
Google ไม่ตัดเงินถ้าอยู่ในโควตา Always Free

> ถ้าบัตรไม่ผ่านที่นี่อีก ให้ข้ามไปทาง "เครื่องที่โรงเรียน + Cloudflare Tunnel" แทน
> ซึ่งไม่ต้องใช้บัตรเลยและไม่มีโควตาขาออก

## 2. สร้างเครื่อง — จุดที่พลาดแล้วเสียเงินโดยไม่รู้ตัว

**Compute Engine → VM instances → Create instance**

- **Name**: `esaraban`
- **Region**: ต้องเป็น `us-west1`, `us-central1`, หรือ `us-east1` เท่านั้น
  ภูมิภาคอื่น**ไม่ฟรี** แม้จะเลือกเครื่อง e2-micro ก็ตาม
- **Machine type**: `e2-micro` (Series E2 → Shared-core → e2-micro)
- **Boot disk**: กด Change แล้วตั้ง
  - Image: **Ubuntu 24.04 LTS**
  - Size: **30 GB**
  - Disk type: **Standard persistent disk** ⚠️

  ข้อสุดท้ายสำคัญมาก — ค่าเริ่มต้นของ Google คือ **Balanced persistent disk (SSD)**
  ซึ่ง**ไม่อยู่ในโควตาฟรี** ถ้าปล่อยไว้จะถูกคิดเงินเดือนละไม่กี่สิบบาทไปเรื่อยๆ โดยไม่มีอะไรเตือน
  เพราะเครื่องก็ทำงานปกติดี มีแต่บิลที่โตขึ้น
- **Firewall**: ติ๊ก ✅ **Allow HTTP traffic** และ ✅ **Allow HTTPS traffic**

  ต่างจาก Oracle ที่ต้องเปิดพอร์ตสองชั้น — Google เปิดให้ชั้นเดียวจากหน้านี้ และอิมเมจ Ubuntu
  ของ Google ไม่มี iptables ปิดกั้นมาให้ตั้งแต่แรก ติ๊กสองช่องนี้แล้วจบ

กด **Create** แล้วจดเลข **External IP** ไว้

**เข้าเครื่อง**: กดปุ่ม **SSH** ในคอนโซลได้เลย เปิดในเบราว์เซอร์ ไม่ต้องจัดการกุญแจเอง
(ง่ายกว่า Oracle ที่ต้องดาวน์โหลดไฟล์กุญแจมาเก็บ)

## 3. ⚠️ RAM 1 GB ไม่พอตอนประทับตรา — ต้องมี swap

นี่คือข้อที่ต่างจาก Oracle มากที่สุด เครื่อง A1 ของ Oracle มี RAM 12 GB ส่วน e2-micro มี 1 GB

การประทับตราลงไฟล์ PDF ต้องเปิด Chromium ขึ้นมาพิมพ์แผ่นตราเป็นไฟล์ PDF ซึ่งกินหน่วยความจำ
เป็นก้อนใหญ่ **วัดจากของจริงใต้เพดานหน่วยความจำ 1 GB** (จำกัดด้วย cgroup ใช้โปรแกรมและไฟล์
ชุดเดียวกับที่ใช้งานจริง):

| สถานการณ์ | หน่วยความจำสูงสุดที่ใช้ | ผล |
|---|---|---|
| ประทับตรา 1 รายการ | 309 MB | ผ่าน |
| ประทับตรา 3 รายการพร้อมกัน | 845–943 MB | ผ่าน แต่เหลือที่ว่างไม่ถึง 180 MB |

ตัวเลขชุดนี้**ยังไม่รวม**ระบบปฏิบัติการกับตัวแอปที่ค้างอยู่ในหน่วยความจำอีกราว 300 MB
แปลว่าบนเครื่อง 1 GB จริง ถ้าครูสามคนกดประทับตราพร้อมกัน เคอร์เนลจะฆ่าโปรเซสทิ้ง (OOM killer)
อาการที่ครูเห็นคือ**หน้าเว็บค้างหรือระบบหลุดไปเฉยๆ ไม่มีข้อความบอกสาเหตุ** และหาสาเหตุยากมาก
เพราะเกิดเฉพาะตอนที่คนใช้พร้อมกันหลายคน

swap ทำให้กรณีนั้นกลายเป็น **"ช้าลง" แทน "ระบบล่ม"** — ช้ากว่าแต่ยังได้งาน

**สคริปต์ `setup-ubuntu.sh` ในข้อ 4 เพิ่ม swap 2 GB ให้เองแล้ว** เมื่อเห็นว่า RAM น้อยกว่า 2 GB
พร้อมใส่ `/etc/fstab` ให้กลับมาเองหลังรีสตาร์ท และตรวจผลตอนจบว่าหน่วยความจำรวมพอหรือยัง

ถ้าติดตั้งด้วยมือ ต้องทำเองดังนี้:

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # ไม่ใส่บรรทัดนี้ swap จะหายทุกครั้งที่รีสตาร์ท
sudo sysctl -w vm.swappiness=20
swapon --show                                                 # ต้องเห็น /swapfile 2G
```

## 5. ⚠️ ข้อมูลขาออกฟรีแค่ 1 GB/เดือน

เรื่องนี้ควรห่วงมากกว่าดิสก์ เพราะเป็น**ปัญหาเดียวกับที่เจอบน Render**

ระบบส่งไฟล์ PDF ให้ครู**ผ่านตัวเซิร์ฟเวอร์** ไม่ได้ส่งต่อไปที่ Google Drive ตรงๆ
(ดู `downloadFileStream` ใน `src/routes/documents.js`) ทุกครั้งที่ครูเปิดหนังสือหนึ่งฉบับ
ขนาดราว 1 MB จะถูกนับเป็นข้อมูลขาออก → **เปิดได้ราวเดือนละ 1,000 ครั้ง** ก่อนเริ่มคิดเงิน

ต่างจาก Render ตรงที่ **เกินแล้วคิดเงิน ไม่ตัดบริการ** และราคาไม่แพง (หลักไม่กี่บาทต่อ GB)
แต่ต้องมีบัตรที่ใช้ได้ค้างไว้ ไม่งั้นโครงการจะถูกระงับ

วิธีลดจริง:

- **ตั้ง `BACKUP_INTERVAL_MINUTES=60`** ใน `/etc/esaraban.env` (ค่าเริ่มต้น 5 นาที)
  บนเครื่องนี้มีดิสก์ถาวรอยู่แล้ว ไฟล์สำรองบน Drive จึงเป็นแค่ชั้นสำรอง ไม่ต้องถี่เท่าตอนอยู่ Render
- ตั้งงบเตือนที่ **Billing → Budgets & alerts** ให้อีเมลมาเตือนเมื่อถึงยอดที่กำหนด
  ทำข้อนี้ก่อนเลยครับ เพราะเป็นตัวที่จะบอกว่ามีอะไรผิดปกติก่อนบิลจะโต

## หมายเหตุ: ดิสก์ 30 GB จะไม่เต็ม

เมื่อต่อ Google Drive แล้ว **ไฟล์แนบไม่ลงดิสก์เครื่องเลย** ส่งขึ้น Drive ตรงๆ
(โฟลเดอร์ `uploads/` ถูกใช้เฉพาะตอนที่ยังไม่ได้ต่อ Drive — ดู `src/services/attachments.js`)

ดิสก์ 30 GB จึงเหลือแค่ระบบปฏิบัติการ + Chromium/ฟอนต์/qpdf (ราว 6–8 GB) + ตัวฐานข้อมูล SQLite
ซึ่งเก็บแต่ข้อความ (เลขที่ เรื่อง จากใคร ถึงใคร) ไม่ได้เก็บไฟล์ โตราว 10–20 MB ต่อปี

**ตัวที่จะเต็มก่อนคือ Google Drive 15 GB** เพราะ PDF ทั้งหมดอยู่ที่นั่น ระบบรองรับไว้แล้ว:
ต่อไดรฟ์ที่สองได้ และจดไว้ที่ตัวไฟล์ว่าไฟล์ไหนอยู่ไดรฟ์ไหน (`src/services/driveAccounts.js`)
พร้อมเตือนบนแดชบอร์ดผู้ดูแลเมื่อไดรฟ์เต็ม

ถ้าอยากขยายดิสก์จริง GCP ขยายได้ทันทีไม่ต้องปิดเครื่อง (`gcloud compute disks resize`
แล้ว `sudo resize2fs /dev/sda1`) ขยายได้ ย่อไม่ได้ ส่วนที่เกิน 30 GB เสียเงินตามจริง

## ย้ายมาจาก Render

Render แผนฟรีไม่มีดิสก์ถาวร ฐานข้อมูลถูกล้างทุกครั้งที่ deploy ใหม่ ของที่ยังอยู่จึงมีแค่ที่เพิ่งใส่
หลัง deploy ครั้งล่าสุด **โดยปกติไม่ต้องย้ายอะไรเลย** — ตั้งต้นใหม่บนเครื่องนี้ได้

ที่ต้องทำคือ**ย้ายค่าตั้งค่า** จาก Environment ของ Render มาใส่ `/etc/esaraban.env`
โดยเฉพาะชุดที่หายแล้วกู้ไม่ได้:

```
GOOGLE_OAUTH_CLIENT_ID / GOOGLE_OAUTH_CLIENT_SECRET / GOOGLE_OAUTH_REFRESH_TOKEN
LINE_CHANNEL_ACCESS_TOKEN / LINE_CHANNEL_SECRET
OUTGOING_NUMBER_START / OUTGOING_NUMBER_START_YEAR
```

เมื่อใส่ `GOOGLE_OAUTH_REFRESH_TOKEN` ครบแล้ว ระบบจะ**กู้ฐานข้อมูลจากสำเนาล่าสุดบน Drive
ให้เองตอนเริ่มระบบ** (ดู `restoreDatabaseIfMissing` ใน `src/services/dbBackup.js`) —
ทะเบียนหนังสือทั้งหมดกลับมาเองโดยไม่ต้องคัดลอกไฟล์ด้วยมือ

สุดท้ายอย่าลืม:

1. ตั้ง `PUBLIC_BASE_URL=https://<โดเมนของโรงเรียน>` แล้ว `sudo systemctl restart esaraban`
2. แก้ Webhook URL ของ LINE ที่ `developers.line.biz` ให้ชี้มาที่โดเมนใหม่
3. **ปิด service บน Render ทิ้ง** เพื่อไม่ให้มีสองระบบที่ข้อมูลคนละชุดเปิดอยู่พร้อมกัน แล้วครูเข้าผิดที่
